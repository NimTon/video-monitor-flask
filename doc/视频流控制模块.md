## 模块名称  
视频流控制模块 `video_stream.py`

## 模块定位  
该模块是系统的实时视频处理核心，负责从视频流中采集帧数据、管理电子围栏检测器、定时分析画面变化并触发后续 AI 判别与报警逻辑。它以线程形式运行，可同时管理多个视频流任务，是整个监控识别流程的起点。

## 技术栈与依赖  
- Python 3.x  
- OpenCV 4.x：用于图像帧采集与处理  
- 多线程 `threading`：支持并发处理多个视频流  
- 自定义围栏检测器：`FenceChangeDetector`（见 `fence_detector.py`）

## 输入与输出  
- **输入**：
  - `stream_url`：视频流地址（支持 RTSP、HLS 等）
  - `fences`：围栏坐标点数组（通过 `set_fences()` 设置，来源于 JSON 配置）
- **输出**：
  - 每个围栏检测结果（是否发生变化、变化区域大小、变化比例等）
  - 若检测到变化：过去数秒的关键帧列表（每秒一帧）
  - 所有结果通过 `result_callback()` 回调给上层模块处理（如 AI 判断与报警）

## 核心功能与逻辑说明  

### 类结构
```python
class VideoStreamThread(threading.Thread)
````

继承自 `threading.Thread`，每个实例代表一个独立的视频流监听处理任务。

### 核心逻辑流程

1. **启动线程并初始化视频流**：

   * 调用 `cv2.VideoCapture(stream_url)` 打开流；
   * 自动获取帧率，确定处理节奏。

2. **循环采集帧**：

   * 每帧都存入 `frame_buffer`，保存时间戳及画面内容；
   * 当到达设定的 `compare_interval`（默认 10 秒）时，触发围栏变化检测。

3. **围栏检测与图像筛选**：

   * 使用每个围栏对应的 `FenceChangeDetector` 对当前帧与上一次帧做对比；
   * 若检测到变化，则从缓存中每秒抽取一帧，组成 `frames_to_return`。

4. **结果回调**：

   * 将围栏变化结果和图像帧传给 `result_callback()` 供后续处理模块使用（如 AI 判别模块、报警推送模块）。

5. **帧缓存清理并继续下一轮检测**。

### 示意时序图

```
[视频帧采集] ---> [缓存帧数据]
        |
   达到compare_interval
        ↓
[围栏检测] ---> [抽取帧] ---> [结果回调]
```

## 配置说明

| 参数名                | 说明                  | 默认值   |
| ------------------ | ------------------- | ----- |
| `compare_interval` | 每次检测间隔（秒）           | 10.0  |
| `change_threshold` | 判断围栏是否“变化”的阈值（面积比例） | 0.1   |
| `debug`            | 是否展示实时画面窗口（调试用）     | False |

## 与其他模块的交互

* 从 `video_fences.json` 加载视频流与围栏配置（由 `storage.py` 管理）；
* 检测到变化后调用 `alert_dispatcher.py` 提交截图帧与检测结果；
* 提交给 `qwen_ai.py` 分析图片内容，确认是否真正异常；
* 触发报警模板合成并推送（由 `alert_dispatcher.py` 调用多种 API）；
* 前端界面 `MonitorView.vue` 可通过 `Flask` 接口控制此模块的启动/停止状态。

## 调试建议

可独立运行并查看图像变化情况：

```bash
python video_stream.py --debug
```

或设置 `debug=True` 后在 Flask 服务中启动对应线程，命令行窗口会弹出视频帧画面，用于围栏调试。
